# AOMQTT roadmap update after v0.7

| Version | Main purpose | Status |
|---|---|---|
| v0.1 | Minimal SDK | Paho wrapper, HMAC topic tokenization, AES-GCM |
| v0.2 | Token mode comparison | `hierarchical` / `whole` |
| v0.3 | Long-term tracking mitigation | epoch token rotation and overlap window |
| v0.4 | Implementation foundation | transport adapter separation and client-side observation foundation |
| v0.5 | Evaluation foundation | publisher/subscriber CSV, delivery loss, duplicates, decryption results |
| v0.6 | Payload size leakage mitigation | `none`, `bucket`, `fixed`, `random` padding and overhead evaluation |
| v0.7 | External policy control | policy YAML, policy matrix evaluation, config/policy separation |
| v0.8 | Observation-driven control | automatic policy adjustment from latency/loss/duplicate/overhead metrics |
| v0.9 | High-performance implementation | Rust core or Rust client SDK |
| v1.0 | Reproducible paper package | Docker, scripts, plots, stable docs |

## v0.7 scope boundary

v0.7 intentionally supports manual or externally supplied policy changes only.
It does not yet implement automatic control. Examples:

- A human/operator selects `whole + bucket + rotation`.
- A file generated by an external controller is applied with `--policy`.
- A matrix of policies is evaluated with `run_policy_evaluation.py`.

## v0.8 direction

v0.8 should add a controller that consumes v0.5/v0.6/v0.7 metrics and changes
policy according to rules such as:

- increase overlap if loss appears around rotation boundaries;
- reduce padding size when PUBACK latency or bandwidth overhead exceeds a threshold;
- choose `hierarchical` when MQTT wildcard compatibility is needed;
- choose `whole` when structure leakage reduction is prioritized;
- shorten rotation interval when linkability risk is prioritized.
