# v1.1.0 Trusted Policy Delivery and Key Lifecycle Hardening

v1.1.0 extends the v1.0.2 client-side Policy Guard by adding a trust validation layer for signed policies.

## Scope

- Sign policy envelopes through `PolicySigner`.
- Verify signed policy envelopes on the client side.
- Reject policies signed by unknown keys.
- Reject policies signed by revoked keys listed in a KRL.
- Reject tampered policies whose signature no longer matches the policy body.
- Preserve policy id and sequence number in rejected ACK/status payloads.

## Validation flow

```text
Control policy received
  -> extract policy.id / sequence_no
  -> extract signer key id
  -> reject unknown key id
  -> reject revoked key id
  -> verify Ed25519 signature
  -> pass accepted policy to Policy Guard
  -> publish accepted/rejected ACK
```

## Intended integration point

`aomqtt.policy_trust.verify_signed_policy_envelope()` should be called before constructing or applying the concrete `ControlPolicyMessage` object. This keeps rejected ACKs traceable even when policy parsing fails later.
