# v0.9.2 Controller-side Analysis

v0.9.2 adds Controller-side analysis utilities for the AOMQTT evaluation workflow.
The goal is to make policy deployment feedback easier to compare before the v1.0.0 research-prototype release.

## Purpose

v0.9.1 introduced runnable evaluation scenarios.  v0.9.2 focuses on analysis of the Controller-side feedback produced by those scenarios:

- ACK aggregation across runs and scenarios
- status aggregation across runs and scenarios
- reason_code aggregation for rejected or failed deployments
- client-level summary generation
- paper-ready comparison CSV generation

## Command

Run the default analysis with:

```bash
./experiments/collect_v092_controller_analysis.sh
```

Analyze a specific run:

```bash
RUN_ID=run-v091-final-check ./experiments/collect_v092_controller_analysis.sh
```

Analyze multiple runs:

```bash
RUN_ID=run-a,run-b ./experiments/collect_v092_controller_analysis.sh
```

Use custom directories:

```bash
RESULTS_DIR=results OUTPUT_DIR=results/v092_controller_analysis ./experiments/collect_v092_controller_analysis.sh
```

## Output files

The script writes the following files under `results/v092_controller_analysis/` by default:

- `controller_events_normalized.csv`
- `controller_deployment_summary.csv`
- `controller_deployment_summary.json`
- `controller_client_summary.csv`
- `controller_reason_code_summary.csv`
- `controller_comparison_summary.csv`

## Expected input layout

The loader recursively scans the results directory.  A typical layout is:

```text
results/
  run-v091-final-check/
    static_policy/
      controller_ack.csv
      controller_status.csv
    observation_policy/
      controller_ack.csv
      controller_status.csv
    rejected_policy_feedback/
      controller_feedback.jsonl
```

The CSV/JSONL loader accepts common field names such as:

- `client_id` or `client`
- `policy_id` or `policy`
- `sequence_no`, `sequence`, or `seq`
- `ack_status`, `application_status`, `status`, or `result`
- `reason_code`, `reason`, `error_code`, or `message`

## Main metrics

`controller_deployment_summary.csv` contains:

- `ack_total`
- `ack_accepted`
- `ack_rejected`
- `ack_timeout`
- `ack_accepted_rate`
- `ack_rejected_rate`
- `ack_timeout_rate`
- `status_total`
- `status_applied`
- `status_failed`
- `status_timeout`
- `status_applied_rate`
- `status_failed_rate`
- `status_timeout_rate`

These values are intended for comparing static Policy, observation-driven Policy, and rejected Policy feedback scenarios.
